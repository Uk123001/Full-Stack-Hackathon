8. OTP + EMAIL FLOW
---------------------------------------------------------------------
- 6-digit numeric OTP, generated with crypto (not Math.random).
- Store only a HASH of the OTP. Expiry: 5 minutes.
- Max 5 verification attempts, then lock and require a new OTP.
- Resend cooldown: 30-60 seconds; limit resends per hour.
- Use OTP for: [SIGNUP EMAIL VERIFICATION / LOGIN 2FA / PASSWORD RESET].
- Emails to send (clean, branded HTML templates):
    1. OTP email
    2. Welcome email after verification
    3. [CONFIRMATION / STATUS-UPDATE EMAIL FOR YOUR FEATURE]
- Frontend: 6-box OTP input component, countdown timer, resend button,
  clear error messages.
- Provide a DEV fallback: if SMTP is not configured, log the OTP to the
  server console so the demo never breaks.

---------------------------------------------------------------------
9. CAPTCHA
---------------------------------------------------------------------
- Place captcha on: [REGISTER, LOGIN, FORGOT PASSWORD, PUBLIC SUBMISSION
  FORMS].
- Frontend sends the captcha token with the request.
- Backend middleware verifies the token with the provider's verify API
  using the secret key from env. Reject with 400 if missing/invalid.
- Never trust client-side-only captcha.
- Use the provider's test keys in .env.example so the project runs
  immediately.

10. FORMS + CONDITIONAL VALIDATION RULES
---------------------------------------------------------------------
Build forms with react-hook-form + Zod. Validate on BOTH client and
server with the same rules. Show inline, field-level error messages.

General rules:
  - Email: valid format; password: min 8 chars, upper, lower, number,
    special char; confirm password must match.
  - Phone: [COUNTRY FORMAT, e.g. 10-digit Indian mobile starting 6-9].
  - Trim inputs; block empty/whitespace-only values.

Conditional rules (examples - replace/extend with mine):
  - IF [FIELD A] = "[VALUE X]" THEN [FIELD B] is REQUIRED and must be
    [RULE].
  - IF [FIELD C] = "Yes" THEN show [FIELD D] and require it.
  - IF [ROLE] = "Student" THEN require [College, Year, Roll No];
    IF [ROLE] = "Professional" THEN require [Company, Experience].
  - IF [AGE/DOB] indicates under 18 THEN require [GUARDIAN NAME/CONSENT].
  - IF [START DATE] is set THEN [END DATE] must be after it.
  - IF [TYPE] = "Other" THEN require a free-text "Please specify".
  - Hide and clear dependent fields when their condition becomes false,
    and do not submit hidden values.
Implement conditional logic with Zod `superRefine` / discriminated unions
on the client and the same logic on the server.
